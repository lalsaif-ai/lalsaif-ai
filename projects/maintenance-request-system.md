# University Maintenance Request System

**Course:** IS413 — System Analysis and Design, Majmaah University.  
**Role:** Team project with Aljwharah Alfares.  
**Stage:** Academic analysis and design.

## Problem

Campus maintenance reports can become difficult to track when they arrive through separate channels. The proposed system keeps a request record, a status and an assigned technician.

## Designed workflow

1. A student or staff member submits a facility problem.
2. The administrator assigns a technician.
3. The technician updates progress and adds a work note.
4. The requester follows the status; the administrator reviews reports.

## Deliverables

System overview and requirements; data-flow diagrams; ER/data modeling; UML use cases; an input-form design; and a maintenance-status report design.

The modeled relationship permits a technician to handle multiple requests while each request has at most one assigned technician at a time.

Source: `IS413_University_Maintenance_Request_System.pdf` and the course project materials. This is a system-design submission, not a deployed maintenance service.

**Skills:** requirements analysis, DFDs, ER modeling, UML, interface/report design and technical presentation.
